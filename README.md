# okp-airgapped-signer

Simple signers written in pure JavaScript and pure Nushell,
for play and for air-gapped devices.
Basic untrusted alternatives to `ssh-keygen -Y sign`: what they produce is an SSHSIG signature that `ssh-keygen -Y verify` checks.

The code was generated by different generations of Claude Code models,
without any professional audit and with no understanding of cryptography.

Tools can:

- derive a key from a BIP39 mnemonic seed phrase, with optional passphrase
- sign arbitrary text strings

The JavaScript implementation can output QR codes of public keys and signatures.

The Nushell implementation can check a signature it made against the key it derived.

`test/` holds optional probes for the JavaScript signer, most of them driving the page in jsdom; see `test/README.md`.

`specs/main.md` states what both signers must satisfy; `specs/js-okp-signer.md` and `specs/nu-okp-signer.md` hold what is true of one of them alone.

## JavaScript signer: `js-okp-signer/index.html`

One self-contained file.
It runs from `file://` in a desktop browser, and the folder around it is a GitHub Pages site, so it also runs as a Home Screen web app on iPhone, where a local HTML file cannot run its scripts without extra software.

To host it: repository Settings, Pages, source "GitHub Actions", set before the first push to `master`, or that first run fails with "Pages not enabled".
The workflow in `.github/workflows/pages.yml` publishes `js-okp-signer/` on every push to `master`, and the app then lives at `https://<user>.github.io/<repo>/`.
On iPhone open that URL in Safari, share, "Add to Home Screen".
The Home Screen app has its own storage, separate from Safari, so launch it once while online: the service worker in `js-okp-signer/sw.js` caches the page on that first launch, and the app works with no network after that.
The footer shows `offline copy: ready, version ...` when the cache is in place.

When any file in `js-okp-signer/` changes, bump `VERSION` in `js-okp-signer/sw.js`.
That is the only file the browser refetches past the cache, so without the bump an installed app keeps the old page.

To check that the hosted page is the one in git, without any software on the phone, a three-action Shortcut: "Get Contents of URL" with the app URL, "Generate Hash" SHA-256, "Show Result".
Compare with the hash from git on the desktop:

```
git show master:js-okp-signer/index.html | sha256sum
```

The shortcut hashes what the server serves now, not what the phone has cached, so a match proves the server and says nothing about the installed app.
The service worker keeps the page it fetched on the first launch until `VERSION` changes, so an app installed while the site served a wrong page keeps that page after the site is fixed, and the check still passes.
To make the phone hold the page just checked, remove the Home Screen app and add it again right after a match: the new install fetches the page the server serves at that moment.

## Nushell signer: `nu-okp-signer/`

Pure Nushell, no external command and no library, so the air-gapped machine needs nothing but `nu`.
From the repository root:

```
use nu-okp-signer
let key = nu-okp-signer derive              # prompts for the mnemonic and the passphrase, about 16 s
let sig = "text" | nu-okp-signer sign $key  # the SSHSIG block
"text" | nu-okp-signer verify $key $sig     # true or false
```

Both signers sign under the SSHSIG namespace `file` unless told otherwise.
Git checks a commit's signature under `git`,
so a commit object (`git cat-file -p HEAD`, signed raw) takes `--namespace git` here,
or `git` in the namespace field on the page.

`help nu-okp-signer derive` prints the documented test vectors with the fingerprint each must give, so the module can be checked by hand where no test toolchain exists.
